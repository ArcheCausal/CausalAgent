# 因果效应门禁设计

文档职责：说明效应估计的诊断、查询匹配、函数形式检查与最终决策边界；当前运行事实统一见[Agent 运行时](../architecture/agent-runtime.md#因果效应估计与最终门禁)。

适用范围：`causal.backdoor_ols` 与 `causal.g_formula` 的图引用、调整集准入、诊断记录、查询匹配和最终决策；不增加分类编码、其他估计器、自动补调或额外重试。

## 触发与完成条件

分析路由中，`analysis_parameters.treatment` 与 `target` 已绑定为不同变量，且本次认可的结果集合存在通过源算法结构校验的有效发现图时，必须对当前查询完成一次 `effect_diagnose`。参数中的角色在进入这里之前已由 `execution_parameters()` 解析为实际列名；触发条件来自已绑定参数，与问题文本语言和关键词无关。

诊断结论使用 `verdict=proceed|reject|error`，账本状态另记为 `succeeded|not_applicable|failed`。`proceed` 与 `reject` 都算已有结论：`proceed` 要求用同一张图完成一次真实估计，未就绪、不适用、失败和超时都保留真实终态；`reject` 保留拒绝理由，不再强制补跑。`error` 表示诊断没有完成，不能替代结论。改为 `evidence_only` 不免除已经触发的要求。

## 查询记录与结果匹配

算法与诊断调用在终态账本保存程序生成的 `effect_query`，字段为源图引用、处理变量、结果变量，以及 g-formula 的对比区间与结局模型。值只来自已校验的工具参数，模型不能补写。诊断比较源图与变量对，估计比较完整请求，因此另一变量对或其他源图的记录不能代替当前查询。缺少查询证明的旧 checkpoint 仍可读取，但不能满足新门禁。

存在有效估计结果时，主结果必须是估计结果，且该估计的源图必须有通过的诊断记录。主图只来自本次通过门禁的结果；报告展示估计的源图。

## 函数形式检查

估计结果出现 `residual_spearman_max` 或 `residual_abs_spearman_max` 达到阈值，或数据集非线性强度达到阈值时，必须存在当前查询的 `causal_g_formula` 调用，并明确使用 `contrast=(0, 1)` 与 `outcome_model=hgb`。线性估计按每单位变化解释，其他对比区间不能参与这项比较；只调用 g-formula 或使用线性结局模型都不满足检查。

只有当前查询诊断为 `proceed`、且信号触发时才要求灵活检查。线性与灵活估计的差值明显时，灵活估计必须成为主结果；灵活检查返回不适用或失败时，判定为未完成，允许以发现图作为主结果，并在报告中说明真实终态。

## 检查与执行边界

共享纯检查先判断图是否适用于当前方法，再取处理变量的全部父节点，生成有序的执行列集合。图不适用且无法生成调整集时，调整集与执行列为 `null`；只有确认为无需调整时才保存空调整集。

Worker 使用可信绑定及其画像初查；MCP 使用权威数据读取、实际 CSV 画像和已保存语义复核。所有参与列都必须存在、采用数值存储且无缺失、常量和非有限值。明确声明为 `category`、`ordinal` 或 `binary` 的参与列返回不适用。不根据整数类型或唯一值数量推断测量语义，未声明语义保留未充分确认的限制。非参与分类列不影响当前估计。

后门 OLS 内核继续检查共线、自由度和数值有限性；g-formula 以同一调整集拟合结局条件均值并做直接标准化。检查失败不删除调整变量、不删除行、不填值、不改图。稳定原因码通过 runner 传递，MCP 只把受控白名单说明放入诊断。顶层继续使用共享错误分类。

结果、工具消息和终态账本通过一个 `Command` 原子发布。预算收尾保留原调用的来源摘要和分析数据集身份，只记录未执行，不生成检查记录。

## 修正与统计边界

门禁沿用一次修正机会，失败后进入现有降级流程。提示说明需要完成的诊断、估计或灵活检查，不自动换图或补调算法。

检查通过不证明图方向正确、无未观测混杂或调整集充分。后门 OLS 提供调整集下的线性总效应与模型内区间；g-formula 提供同一调整集下的条件均值差与 bootstrap 区间，结论不超出这些假设。

## 分层验收

| 层次 | 必须证明的行为 |
|---|---|
| 纯函数与契约 | 全部父节点与列集合、语义及数据拒绝、图原因码、查询记录匹配、诊断与估计门禁、旧结果可读 |
| 实际组件 | Tool → Adapter → MCP → 真实 runner 的记录一致；另一变量对与其他源图不能通过；受控不适用能够通过；函数形式检查的对比区间与结局模型；报告快照与重新生成保留理由；预算收尾身份完整 |
| 真实环境 | HTTP MCP、MySQL 权威绑定、PostgreSQL checkpoint 恢复、预算跳过与完整 Job；环境不可用时明确保留未验收结论 |

专项入口见[测试与验证](../development/testing.md#因果效应估计与函数形式检查)。构造输入用于验证已知条件，不用替代算法或外部服务来声称真实环境验收。
